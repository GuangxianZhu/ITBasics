# v2 双向通信模拟器：清洗机(原IO) ↔ PLC 网关 ↔ 全串口温水器

清洗机软件不改，PLC 把原来的 IO「翻译」成串口。

```
pip install panda3d
python app.py          # 模拟器
python test_codec.py   # 协议框架单元测试
```

## 文件分工（拿到手册后改哪里）

| 文件 | 内容 | 到公司要不要改 |
|---|---|---|
| `codec.py` | 帧编解码（帧头帧尾、ASCII/二进制、BCC/CRC） | **改**：按手册的帧格式写一个新 Codec 类 |
| `command_table.py` | 参数号、位数、倍率、状态位/报警位定义、NAK 码 | **改**：照手册参数一览填 |
| `point_map.py` | 原 IO ↔ 参数的对应、通信异常时输出策略、AD 量程、超时/重发等 | **改**：按实际 IO 表和 AD 规格 |
| `engine.py` | PLC 网关逻辑 + 温水器模型 + 16 个用例 | 一般不改（温水器模型可按手册行为微调） |
| `app.py` | Panda3D 画面 | 不改 |

`codec.py` 里放了两个实现：虚构协议 v2 和 Modbus RTU。画面顶部「协议」按钮可以切换，
引擎和点表一行都不改 —— 这就是框架的意义。

## 核心设计

1. **电平语义 = 期望状态对账**：清洗机的 W0~W3、AD 是期望值；轮询读回的是实际值；
   不一致就重写（限频、限次）。温水器重启后状态丢了也能自动补回。
2. **先远程再其它**：W0 没给、或温水器还没确认进入远程时，其它点不写。
3. **温水器有停机类报警时不硬写「加热」**，等复位后再对账写回。
4. **AD 4-20mA**：用原始值立刻判断断线（<3.6mA），断线时保持原 SV、轻故障 ON；
   正常时滤波 + 等稳定 + 0.5℃ 死区 + 最短写间隔，防止抖动刷屏。
5. **通信异常**：连续 3 次失败 → 锁存 → R4 重故障 ON、R0 Ready OFF；
   通信恢复后不自动解除，等清洗机按 W4 复位（和原 IO 一样）；复位时还不通则拒绝。
6. **急停**是硬线，直接到温水器，不经过 PLC。

## 用例

① 正常启动　② AD 改温度　③ AD 噪声不刷屏　④ AD 断线
⑤ 温水器重启→自动补回　⑥ 485 断线→复位　⑦ 断线中按复位
⑧ 断线·无看门狗（温水器继续加热！）　⑨ 断线·有看门狗（自停）
⑩ 过热　⑪ 漏水　⑫ 轻故障　⑬ 重故障　⑭ 急停　⑮ 线路干扰　⑯ 远程未给

## 到公司要确认的

- 故障信号极性（`point_map.FAULT_ACTIVE_LOW`）
- AD 量程对应温度（`point_map.AD`）
- 新温水器有没有通信看门狗（对比用例 ⑧⑨）
- 新温水器的帧格式、参数表、拒绝码
- 「远程」「在线」是不是一个信号（是的话删掉 `WRITE_POINTS` 一行）
