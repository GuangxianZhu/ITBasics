# 交互方案：水龙头 · 水壶 · 铲子（院落别墅 VillaVR）

> 状态：方案，未动工（2026-10-18）。等 Visual Studio 装完再开始。
> 证据分级：✅ 公认/实测　⚠️ 未验证　💭 推测

## 0. 串成一条玩法

香草厨园本来就有 **石水槽 + 龙头**（静态模型）和 4 个种植池，正好串起来：

**拧开龙头 → 水壶接水（水位上涨）→ 走到种植池倒水浇花（土变深色）→ 用铲子松土/挖坑**

三个东西共用一套"水"：水流特效 + 容器里的水量变量 + 被浇的表面变湿。

## 1. 水龙头（最简单，建议第一个做）

- 手柄不是"抓起来"，而是"抓住后绕轴转"：VR 模板 `GrabComponent` 的抓取类型设 **Custom**，只收"被抓/松开"事件，自己算角度。✅ 主流做法
- 角度算法：把手的位置投影到龙头转轴的垂直平面上，算和起始方向的夹角，限制在 0–90°。不用物理约束（Physics Constraint 在 VR 里容易抖）。✅
- 开度 0–1 → 控制 Niagara 水流的生成速率和粗细、流水声音量。
- 下面放一个 Box 碰撞当"接水区"：水壶口在里面就加水。

## 2. 水壶（核心难点：什么时候出水）

- 判断出水：**壶嘴口的世界高度 低于 壶内水面高度** 时才出水（水面始终水平）。所以水越少，要倾得越斜才出水。✅ 物理上成立；💭 实现上用"水量→水面高度"查表近似即可
- 出水速率 ∝ 高度差（可以用 √高度差，近似托里拆利定律）。
- 水流：Niagara 粒子带重力 + 碰撞事件；落到种植池（带 Tag）就让土的材质参数"湿度"上升。
- 壶内水面：壶内一个平面网格，材质用世界坐标保持水平；或者只做外观不可见（壶不透明时最省事）。
- 不用 Niagara Fluids（真流体）：⚠️ 太重，VR 90 帧（forward 渲染）预算撑不住。

## 3. 铲子（最难，三档可选）

| 档 | 做法 | 效果 | 难度 |
|---|---|---|---|
| A | 铲尖碰到土 + 向下速度够 → 在土面贴"坑"贴花 + 生成一团土块（可抓） | 像样，假 | 低 |
| B | 种植池土面换成 **Dynamic Mesh**（Geometry Script），铲到就压低附近顶点 | 真变形，只限小块土 | 中 |
| C | 体素插件（Voxel 类） | 能真挖洞 | 高，⚠️ 插件兼容/性能未知 |

推荐 B（只在 4 个种植池范围内变形，顶点少，VR 性能没压力 💭）。
双手握铲：主手抓柄端、副手抓中段，铲子方向由两手连线决定。

## 4. 用蓝图还是 C++

- 现在的远程流程是"蓝图 DSL 逐节点写"，坑多（节点名会变、中文界面接错线）。
- 装好 VS 后可以改成：**C++ 写 3 个组件**（`UFaucetHandle`、`UPourable`、`UDiggable`），蓝图只负责摆放和调参数。✅ C++ 基类 + 蓝图配置是 UE 主流做法
  - 好处：Claude 远程写文本代码比拼节点稳得多，能 diff、能进仓库。
  - 代价：工程变成 C++ 工程，打开前要先编译；编译失败就打不开（需要保留回退方法）。
- ⚠️ 未验证：UE 5.8 对 VS 2026 的支持情况；已装的 VS 生成工具 2022（17.14）可能也够 UBT 编译。装完后先跑一次空 C++ 类编译测试。
