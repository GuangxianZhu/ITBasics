# 外包 PLC 程序审查指南（GX Works3 + 公司 Copilot）

> 适用：外包用三菱 GX Works3（iQ-R 系列）做的程序，我不会写 PLC，要借公司 Copilot 找疑点。
> 原则：**AI 负责翻译和找疑点，结论由人（外包确认 / 实机测试）定。** 只用公司批准的 Copilot。

---

## 第 0 步：在 GX Works3 里摸清能导出什么（约 5 分钟，只做一次）

逐个试，在右边打勾：

| # | 试什么 | 在哪试 | 结果 |
|---|--------|--------|------|
| 1 | 程序导出成 CSV / 文本 | 「プロジェクト」菜单里找「他形式ファイル」「エクスポート」之类 | ☐ 能 ☐ 不能 |
| 2 | 复制梯形图粘贴成文字 | 梯形图里选几行 → Ctrl+C → 粘贴到记事本 / Excel | ☐ 是文字 ☐ 不是 |
| 3 | デバイスコメント 导出 CSV | 导航窗口的「デバイスコメント」→ 右键 / 菜单里找 CSV | ☐ 能 ☐ 不能 |
| 4 | クロスリファレンス / デバイス使用リスト 导出 | 「検索/置換」菜单附近 | ☐ 能 ☐ 不能 |
| 5 | 打印成 PDF（保底） | 「プロジェクト → 印刷」，打印机选 PDF | ☐ 能 ☐ 不能 |

> 第 3 项确定能做（三菱官方有这项功能）。其余几项的菜单名称我没能核实，以实际软件为准。
> 1、2 都不行 → 跳到"附：让外包提交资料"。

---

## 第 1 步：准备材料（全部是文字）

1. **程序文本**：第 0 步的 1 或 2 得到的。**不要打乱行的顺序**。
2. **デバイスコメント CSV**：地址 / ラベル → 名字。
3. **控制对象表、IO 表**：手头已有的。
4. **动作要求**：这段程序"应该做什么"。来自规格书、设计书，或者自己用大白话写几条，例如：
   - 液位到上限时必须停止给水
   - 给水阀和排水阀不能同时打开
   - 急停按下后所有阀关闭

> 程序很长时按功能块或按页分批，一次给 Copilot 的量控制在几十行。

---

## 第 2 步：让 Copilot 翻译（不要直接问"对不对"）

复制下面这段给 Copilot，后面贴上材料 1、2：

```
下面是三菱 GX Works3（iQ-R）PLC 程序的文字版，以及デバイスコメント（地址→名字）。
请按原顺序，逐行（每个ラング/回路）输出一张表，列为：
  行号 | 输出（地址 + 名字）| 逻辑式（用名字，AND/OR/NOT，保留括号）| 一句大白话说明
要求：
- 不要合并、不要省略、不要调整顺序。
- 定时器写出设定时间（K 值换算成秒，写明你的换算依据），计数器写出设定次数。
- SET/RST、上升沿/下降沿（PLS/PLF 等）这类指令要在说明里点明。
- 看不懂的指令原样写出并标"不确定"，不要猜。
```

### 抽查（必做，10 分钟）

挑 **3 行**对照原梯形图自己核一遍，挑最复杂的（有并联、b接点、定时器的）。
- 都对 → 继续
- 有错 → 把错的行指出来让它重翻；错得多就分小批重来

---

## 第 3 步：让 Copilot 对照要求找疑点

```
下面是上一步的翻译表，以及控制对象表 / IO 表 / 动作要求。
请找出疑点，每条写：行号、疑点类型、依据（引用哪条要求或哪几行）、建议向外包确认的问题。
重点检查：
1. 动作要求里的每一条，程序里有没有对应的行？没有的列出来。
2. 同一个输出（线圈）是否在多行里被写（双线圈）？
3. 互锁：不该同时动作的输出，有没有互相挡住？
4. 停止 / 急停 / 异常条件，是否能让相关输出全部 OFF？
5. 定时器、计数器的设定值是否和要求一致？计数器有没有复位？
6. IO 表里有、程序里没用到的输入输出；程序里用到、IO 表里没有的地址。
只列疑点，不要下"程序正确"的结论。
```

---

## 第 4 步：整理成确认清单

把 Copilot 列的疑点自己过一遍，删掉明显误报的，剩下的整理成表发给外包：

| No. | 行号 | 疑点 | 想确认的问题 | 外包回答 | 结论 |
|-----|------|------|-------------|---------|------|

结论只有三种：**没问题（有理由）/ 需修改 / 实机测试确认**。

---

## 附：让外包提交资料（自己导不出时）

向外包要：
1. 程序的文字版（CSV / 文本导出，或打印 PDF）
2. デバイスコメント CSV
3. クロスリファレンス（交叉引用）表
4. 各回路的功能说明（一行一句即可）

这些是审查资料，要求提交属于正常范围。

---

## 常见坑

- **行的顺序有意义**：PLC 从上往下逐行执行，同一个输出被写两次时，**后面那行说了算**。
- **ラベル**：iQ-R 程序常用标签名代替 X0/Y0。导出文本里可能是标签名，要同时拿到标签和实际地址的对应表。
- **混合语言**：程序里可能混有 ST 语言或功能块（FB）。FB 内部要单独导出、单独审查。
- **AI 会编**：遇到不认识的指令，它可能猜一个意思。所以要求它标"不确定"，也要做抽查。
- **审不出时序问题**：AI 读代码很难发现"某个信号晚了一个扫描周期"这类问题，这类只能靠实机或仿真测试。
